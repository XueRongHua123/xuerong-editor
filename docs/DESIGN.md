# 雪绒编辑器 · 界面设计纲要

给后续功能（地图涂色、省份细化、AI 面板扩展等）用的约定。每一条都是踩过坑之后定下来的，不是空泛原则。

---

## 一、指针交互：拖动的东西不许选中文字

**问题**：在地图上按住左键拖动，浏览器把文字选中；继续拖出窗口，浏览器把它当成"拖拽"处理，可能打开新页面或搜索。

**约定（新建可拖拽区域必须全部满足）**

1. 容器上 `user-select: none`，并在 `pointerdown` 里 `e.preventDefault()`
2. 容器内所有 `<img>` 设 `draggable = false`；对**动态插入**的图片用 `MutationObserver` 补一遍，不能只在初始化时扫一次
3. 在 `document` 上统一拦截 `dragstart`（`capture` 阶段），界面上没有任何需要浏览器原生拖放的功能
4. 全局拦截 `contextmenu`，但放行输入框与可复制区域

**必须放行的白名单**（否则用户复制不了报错和输出）

```
input, textarea, select, pre, code, [contenteditable="true"],
.selectable, #aiOut, #lintList, #scriptBody, #cpList
```

新写一个面板时，如果里面有需要复制的内容，给容器加 `.selectable`，不要为此放开整个页面。

**检测方法**：拖动 200px 后断言 `window.getSelection().toString().length === 0`。

---

## 二、缩放：所有屏幕坐标都要除以 `uiZoom()`

界面的"大 / 小"档位用的是 CSS `zoom`，而 `getBoundingClientRect()` 返回的是**缩放后的视觉像素**。直接拿它设 `left/top` 会被浏览器再乘一次 zoom，浮层整体偏移。

**约定**

- 悬浮菜单、面板定位、拖动位移、视口夹取，一律 `坐标 / uiZoom()`
- 视口尺寸用 `window.innerWidth / uiZoom()`
- 不要用 `calc(100vh - X)` 去算面板高度，用 JS 设定并夹在视口内

**检测方法**：把界面调到「大」档后，测量菜单各项到锚点的距离是否相等。

---

## 三、写盘：只改指定字段，先备份再返回 diff

**约定**

- 任何写操作前 `snapshot(path)`，写失败不留半成品
- 只改动用户填写的字段；注释、BOM、CRLF、其它键逐字保留
- 返回 `diff` 列表（旧值 → 新值），界面用列表展示，不用弹窗
- 原版目录只读，写请求直接拒绝并给出理由
- 会改二进制（如 `provinces.bmp`）的操作必须"预览 → 确认 → 写盘"三段式，且能整幅回滚

**反例（都真实发生过）**

- 用内存里的 `STATES[sid]["provinces"]` 覆盖文件里的列表，键不匹配时把州写成了空块
- 改了归属后不重建缓存图层，界面显示与文件不一致

---

## 四、数据解析：按游戏的语义来，不要按"看起来对"来

**踩过的坑**

| 现象 | 真实规则 |
|---|---|
| 苏联的州读成 SOV，游戏里是 BETA 巢穴 | `history` 里**日期块**（≤ 开局日期）优先于无日期的直接子级；开局面从 `common/bookmarks` 取 |
| 政治视图整片灰 | `color = rgb { }` / `color = hsv { }` 都是合法写法；mod 的覆盖文件可能只写 `graphical_culture`，缺 `color` 要回退原版同名文件 |
| 装备少了 6 个、科技少了 77 个 | 键名正则要允许 `-` |
| 省份列表截断 | 上限按州规模设，超了要能"显示全部" |

**约定**

- 解析前先确认三件事：**扫哪些根**（mod / 原版）、**取哪一层**（顶层 / 日期块 / 嵌套）、**什么样的名字算定义**
- 拿不准就先只输出计数（"扫描到 N 个定义"），人工抽查 10 条再决定是否展开成清单
- 检查类功能宁可不做，也不刷几百条误报

## 五、图层与模式：一次只改一件事

地图面板的结构（v0.81 起）：

```
左侧模式栏（浏览 / 改归属 / 涂色 / 吸管） → 决定"点击做什么"
画布（多图层叠图）                        → 决定"看到什么"
右侧属性面板                              → 决定"选中对象能改什么"
底部状态栏                                → 决定"现在是什么状态"
```

**约定**

- 新增工具只加一个 `.map-tool[data-mode]` 按钮 + `mapSetMode()` 里的一个分支，不改主逻辑
- 未实现的工具给 `disabled` 并在点击时提示"开发中"，不要静默失败
- 图层开关互斥关系要写进同一个函数（`mapApplyLayers`），不要散落在事件里
- 任何耗时操作（构建缓存 17–24 秒）必须给进度反馈，不能只有转圈

**下一步涂色功能要用到的落点**

- 画笔参数（大小、目标省）放右侧属性面板
- 撤销栈与待写盘改动数放状态栏
- 预览层单独一张画布，不污染已生成的图层缓存

---

## 六、提示：用状态栏，不用 alert

- 操作结果 → 底部状态栏（`status()`），带成功/失败样式
- 需要用户确认的危险操作 → `confirm()`，文案里写清楚"改哪个文件、怎么回滚"
- 长任务 → 顶部进度条 + 面板内秒表（`startLoading / updateLoading / stopLoading`）
- 错误信息保留原文（HTTP 码、文件路径），不要改写成"操作失败"

---

## 七、列表与结果区

- 结果类面板（体检、脚本检查、变体列表）统一用表格：名称 / 类型 / 位置 / 计数
- 危险项（只读、空块、未使用）用颜色区分，并给一句话解释"为什么可能是问题"
- 超过 800 行要提示"用搜索缩小范围"，不要静默截断

---

## 八、跨 mod 兼容

- 任何"读 mod 文件"的地方都要准备回退到原版：`for base in (root, GAME)`
- 缓存键要包含来源绝对路径 + 源文件 mtime/size，不同 mod 互不覆盖
- mod 用共享文件（多 tag 指向同一文件）、缺字段、非标准写法是常态，解析要容错而不是报错退出
- 没有定义的值给稳定派生（如国家色按 tag 哈希），并在文档里说明"不是游戏原色"

## 十、视觉层次：让人眼三秒内找到该看的东西

界面不是"信息平铺"，是**引导视线**。同一屏里元素必须能分出层级，否则用户每个版本都要重新找一遍按钮。

### 1. 文字只分三档，不要更多

| 档位 | 用途 | 取色 |
|---|---|---|
| 主（`--t1`） | 正文、数值、可点击对象名 | `var(--text)` |
| 次（`--t2`） | 标签、说明、未激活项 | `var(--muted)` |
| 弱（`--t3`） | 时间戳、坐标、提示语、元信息 | `muted` 再降 30% |

超过三档会变成"灰得不均匀"，反而更难读。数值用 `font-variant-numeric: tabular-nums` 对齐。

### 2. 主次靠四个手段，不只靠颜色

优先级从高到低：

1. **位置**：主操作放视线终点（右下 / 顶栏最右），不要在左上角和标题抢位置
2. **字号 + 字重**：数值 14–15px/600，标签 11px/400，差 3px 以上才看得出
3. **留白**：相关元素靠近（8px），不相关元素拉开（16–20px）或用分隔线
4. **颜色**：最后才用。accent 只留给"当前状态"和"主操作"，一屏内不超过 2 处

### 3. 状态驱动的强调

不要固定主按钮。**该点的那个按钮才亮**：

- 图层未构建 → 「构建图层」变主按钮；构建完成后自动降级
- 有未保存改动 → 「保存全部」变主按钮；保存后恢复
- 当前工具 / 当前图层 → 加 `.on`，其余保持次色

### 4. 分组比排列重要

同一面板里超过 5 个开关就要分组，并给小标题（10px、字距 1px、弱色）：

```
图层
  数据     省色块 / 政治 / 战略区 / 州
  基础     省界 / 底图 / 透明度
```

分组标题只是"视觉上的分隔"，不需要折叠功能。

### 5. 状态栏是"当前上下文"，不是日志

四段固定顺序，权重递减：

```
[模式徽章 accent] [坐标 弱] [选中摘要 次] ............ [操作提示 最弱]
```

模式用胶囊徽章（边框 + accent 文字），因为它是"我现在在做什么"的锚点。

### 6. 反例清单（都真实出现过）

- 顶栏把标题、元信息、4 个按钮平铺，最右的「关闭」和「构建图层」看起来同样重要
- 属性面板里「州 125」和「像素 87」同样大，用户分不清哪个是判断依据
- 图层 6 个复选框一字排开，没有"数据层 / 基础层"的区别
- 主工具栏 40 个按钮同一尺寸，找不到「保存全部」
- 用 `alert` 报错：既打断操作，又和界面脱节

### 7. 验收方式

- 黑白截图（去色）后仍能分出主次 → 说明靠的是字号/位置/留白，不只是颜色
- 眯眼（失焦）看：能不能一眼找到"下一步该点哪"
- 巡检脚本的 `lowContrast` 只能保证"看得见"，保证不了"分得清"，层次需要人眼复核

### 8. 深色浮层必须用主题令牌，不要硬编码颜色

图层面板一度写成 `background: rgba(10,12,10,.94)`（固定深色），文字却用主题的 `--muted`。
在浅色的「纸页」主题下变成"浅灰字压深灰底"，几乎看不清；在深色主题下也不够亮。

**规则**：浮层的背景与文字必须来自同一套令牌（`var(--panel)` + `var(--t1/--t2)`），
不要出现"写死深色底 + 主题色字"的组合。如果确实需要半透明，用
`color-mix(in srgb, var(--panel) 92%, transparent)`，让两种主题各自成立。

### 9. 全局 `!important` 的幽灵按钮与局部实心按钮

项目的主按钮是"幽灵"风格（透明底、hover 才显底），这组规则带 `!important`。
在地图属性面板里想要实心按钮时，只写 `.mp-acts .btn{background:...}` **不会生效**，
而且同名的 `#mapTools` 选择器在多处重复定义，后定义的会整体覆盖前面的。

**规则**：

- 需要偏离全局样式的局部按钮，用「ID 前缀 + `!important`」显式覆盖，并写明注释为什么
- 同一个选择器（如 `#mapTools`）**只允许出现一次**；要改样式就改原处，不要在后面再写一遍
- 改完用 `getComputedStyle` 抽查 `backgroundColor / borderTopColor`，不能只看截图

### 10. 验收补充

```js
getComputedStyle(el).backgroundColor  // 不能是 rgba(0,0,0,0) 除非设计如此
getComputedStyle(el).color            // 与背景的对比度 ≥ 4.5:1
```

### 检查类功能的分级原则（地图检查 v0.85 起）

体检/检查的结果必须分成三级，级别按**"是否一定是错误"**来定，不按"看起来严重"：

| 级别 | 判据 | 例子 |
|---|---|---|
| 错误 | 数据确定不合法，游戏里一定出问题 | 引用不存在的省 ID、同一省被多个州包含 |
| 警告 | 可能是正常情况，需要人工看 | 省份由多块区域组成（岛屿/飞地）、州不连续、十字交叉像素 |
| 提示 | 统计信息，不一定要改 | 无主省份数量、超大省份（细化候选） |

**不要把"连通性"直接判成错误**：MUVLUV 这类真实地图里，岛屿省、跨海州是常态，第一次跑出 494 条
「省份不连通」时如果标成 error，用户会以为地图烂了。降成 warn 并写清"多为岛屿/飞地"才可读。

配套约定：

- 每条结果给「级别 + 标题 + 一句说明 + 可定位的省列表」
- 结果面板顶部用统计胶囊（错误 N / 警告 N / 提示 N），数量本身就是最重要的信息
- 点击定位要真的跳到地图上（`mapFocusProvince`），否则列表只是文字

### 全局变量与 `window.X` 的坑

`const MAP = {...}` 这样的顶层声明**不会**挂到 `window` 上。
判空写 `if(!window.MAP)` 会永远成立，功能静默走 fallback 分支。

**规则**：同文件内的模块状态直接用词法变量名；只有跨脚本或需要调试时才用 `window.__xxx` 并显式赋值。
