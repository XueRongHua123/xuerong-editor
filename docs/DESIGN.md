# 雪绒编辑器 · 界面设计纲要

给后续功能（地图涂色、省份细化、AI 面板扩展等）用的约定。每一条都是踩过坑之后定下来的，不是空泛原则。

---

## 一、指针交互：拖动的东西不许选中文字

**问题**：在地图上按住左键拖动，浏览器把文字选中；继续拖出窗口，浏览器把它当成"拖拽"处理，可能打开新页面或搜索。

**约定（新建可拖拽区域必须全部满足）**

1. 容器上 `user-select: none`，并在 `pointerdown` 里 `e.preventDefault()`
2. 容器内所有 `<img>` 设 `draggable = false`；对**动态插入**的图片用 `MutationObserver` 补一遍，不能只在初始化时扫一次
3. 在 `document` 上统一拦截 `dragstart`（`capture` 阶段），界面上没有任何需要浏览器原生拖放的功能
4. 全局拦截 `contextmenu`，但放行输入框与可复制区域

**必须放行的白名单**（否则用户复制不了报错和输出）

```
input, textarea, select, pre, code, [contenteditable="true"],
.selectable, #aiOut, #lintList, #scriptBody, #cpList
```

新写一个面板时，如果里面有需要复制的内容，给容器加 `.selectable`，不要为此放开整个页面。

**检测方法**：拖动 200px 后断言 `window.getSelection().toString().length === 0`。

---

## 二、缩放：所有屏幕坐标都要除以 `uiZoom()`

界面的"大 / 小"档位用的是 CSS `zoom`，而 `getBoundingClientRect()` 返回的是**缩放后的视觉像素**。直接拿它设 `left/top` 会被浏览器再乘一次 zoom，浮层整体偏移。

**约定**

- 悬浮菜单、面板定位、拖动位移、视口夹取，一律 `坐标 / uiZoom()`
- 视口尺寸用 `window.innerWidth / uiZoom()`
- 不要用 `calc(100vh - X)` 去算面板高度，用 JS 设定并夹在视口内

**检测方法**：把界面调到「大」档后，测量菜单各项到锚点的距离是否相等。

---

## 三、写盘：只改指定字段，先备份再返回 diff

**约定**

- 任何写操作前 `snapshot(path)`，写失败不留半成品
- 只改动用户填写的字段；注释、BOM、CRLF、其它键逐字保留
- 返回 `diff` 列表（旧值 → 新值），界面用列表展示，不用弹窗
- 原版目录只读，写请求直接拒绝并给出理由
- 会改二进制（如 `provinces.bmp`）的操作必须"预览 → 确认 → 写盘"三段式，且能整幅回滚

**反例（都真实发生过）**

- 用内存里的 `STATES[sid]["provinces"]` 覆盖文件里的列表，键不匹配时把州写成了空块
- 改了归属后不重建缓存图层，界面显示与文件不一致

---

## 四、数据解析：按游戏的语义来，不要按"看起来对"来

**踩过的坑**

| 现象 | 真实规则 |
|---|---|
| 苏联的州读成 SOV，游戏里是 BETA 巢穴 | `history` 里**日期块**（≤ 开局日期）优先于无日期的直接子级；开局面从 `common/bookmarks` 取 |
| 政治视图整片灰 | `color = rgb { }` / `color = hsv { }` 都是合法写法；mod 的覆盖文件可能只写 `graphical_culture`，缺 `color` 要回退原版同名文件 |
| 装备少了 6 个、科技少了 77 个 | 键名正则要允许 `-` |
| 省份列表截断 | 上限按州规模设，超了要能"显示全部" |

**约定**

- 解析前先确认三件事：**扫哪些根**（mod / 原版）、**取哪一层**（顶层 / 日期块 / 嵌套）、**什么样的名字算定义**
- 拿不准就先只输出计数（"扫描到 N 个定义"），人工抽查 10 条再决定是否展开成清单
- 检查类功能宁可不做，也不刷几百条误报

---

## 五、图层与模式：一次只改一件事

地图面板的结构（v0.81 起）：

```
左侧模式栏（浏览 / 改归属 / 涂色 / 吸管） → 决定"点击做什么"
画布（多图层叠图）                        → 决定"看到什么"
右侧属性面板                              → 决定"选中对象能改什么"
底部状态栏                                → 决定"现在是什么状态"
```

**约定**

- 新增工具只加一个 `.map-tool[data-mode]` 按钮 + `mapSetMode()` 里的一个分支，不改主逻辑
- 未实现的工具给 `disabled` 并在点击时提示"开发中"，不要静默失败
- 图层开关互斥关系要写进同一个函数（`mapApplyLayers`），不要散落在事件里
- 任何耗时操作（构建缓存 17–24 秒）必须给进度反馈，不能只有转圈

**下一步涂色功能要用到的落点**

- 画笔参数（大小、目标省）放右侧属性面板
- 撤销栈与待写盘改动数放状态栏
- 预览层单独一张画布，不污染已生成的图层缓存

---

## 六、提示：用状态栏，不用 alert

- 操作结果 → 底部状态栏（`status()`），带成功/失败样式
- 需要用户确认的危险操作 → `confirm()`，文案里写清楚"改哪个文件、怎么回滚"
- 长任务 → 顶部进度条 + 面板内秒表（`startLoading / updateLoading / stopLoading`）
- 错误信息保留原文（HTTP 码、文件路径），不要改写成"操作失败"

---

## 七、列表与结果区

- 结果类面板（体检、脚本检查、变体列表）统一用表格：名称 / 类型 / 位置 / 计数
- 危险项（只读、空块、未使用）用颜色区分，并给一句话解释"为什么可能是问题"
- 超过 800 行要提示"用搜索缩小范围"，不要静默截断

---

## 八、跨 mod 兼容

- 任何"读 mod 文件"的地方都要准备回退到原版：`for base in (root, GAME)`
- 缓存键要包含来源绝对路径 + 源文件 mtime/size，不同 mod 互不覆盖
- mod 用共享文件（多 tag 指向同一文件）、缺字段、非标准写法是常态，解析要容错而不是报错退出
- 没有定义的值给稳定派生（如国家色按 tag 哈希），并在文档里说明"不是游戏原色"

---

## 九、测试与验收

每个版本至少跑一遍：

| 检查 | 命令 |
|---|---|
| UI 元素完整性（JS 引用的 id 都存在） | `python work/check_ui_elements.py` |
| 视觉巡检（27 状态 × 双主题 × 两档视口） | `node work/qa/audit_visual.mjs` |
| 数据写入回归 | `python work/qa/test_v0xx.py` |
| 本次改动的面板实测 | `node work/qa/probe_v0xx.mjs` |

面板类改动必须附一张截图，写清"改前 / 改后"的差异。
