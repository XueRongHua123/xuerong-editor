## 雪绒的钢铁雄心编辑器 v0.67.0

新增「脚本检查」面板：scripted trigger / effect 的定义清单 + 全项目引用计数。

### 为什么不是"检测未使用"

前两版试过自动判定"哪些 trigger/effect 没被用到"，分别误报 1431 条和 399 条（HOI4 的 `OR`、`check_variable`、数字键都会被误认成定义）。
这版换思路：**不猜，只给事实**——列出每个定义的名字、类型、所在文件、以及全项目里 `名字 =` 出现的次数。
次数 1 表示只有定义本身，标黄提示"疑似未使用"，由你自己判断。

### 面板能力

- 搜索（支持中文名，主 mod 有一部分 effect 是中文命名的）
- 按类型筛 trigger / effect
- 排序：引用少→多 / 名称 / 按文件
- 空块单独标注「（空块）」

### 主 mod 实测（muvluvCN 1.19）

- 250 个定义（trigger 104 / effect 146），首次扫描 0.8 秒，之后走缓存
- 137 个只出现一次
- 抽查两条"疑似未使用"，发现它们的引用全在**被注释掉的行**里（`# # ... = yes`），说明报告是对的
- 顺带抓出 19 个空 effect 块：`00_scripted_effects.txt` 里 `bba_create_cas_license_effect` 这类只剩一行注释、块内是空的

### 实现要点

- 定义只认**顶格行**（`^名字 = {`），不再用 `top_items()` 解析层级——这是误报的根源
- 名字支持 Unicode（中文 effect 名）
- 只扫 mod 根，原版目录跳过（原版与 mod 同名是正常覆盖）
- 引用计数扫 `common` / `events` / `history` 下所有 `.txt` 的 `名字 =` 形式

- 视觉巡检 27 个界面状态 × 双主题 × 两档视口全绿
