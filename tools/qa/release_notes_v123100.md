## 雪绒的钢铁雄心编辑器 v1.23.10

技术债第 1 项：撤销备份不再按包围盒存。

### 原来的问题

`map_edit_commit` 存撤销的方式是：算所有改动像素的**包围盒**，把整块区域读出来存盘。

一次改散布在图两头的几百个像素，包围盒就覆盖整张 5632×2048 的图：

```
5632 × 2048 × 3 字节 = 33.0 MB
```

改几次就几百 MB。实际改的只有几百个像素。

### 改法

按稀疏度选存储方式：

```python
area = w * h
use_points = area > 0 and len(pend) < area * 0.35
```

- **密度 < 35%** → 点级备份（每个像素 7 字节：4 字节索引 + 3 字节 RGB）
- **密度 ≥ 35%** → 仍然存包围盒（密集改包围盒更省）

点级备份用的就是已有的 `_save_point_undo` / `_load_point_undo` / `_apply_point_undo`，
注释里本来就写着「散布型改动（十字交叉修复）用包围盒备份会长到几十 MB」，
只是主流程没用上。

### 实测

```
地图 5632×2048

稀疏 200 像素（包围盒 33.0 MB）
  backup 类型: points
  备份文件 1404 字节          ← 33 MB → 1.4 KB

密集 100 像素（包围盒 10×10 = 300 字节）
  backup 类型: rect
  备份文件 300 字节           ← 合理

撤销: restored 100            ← 点级撤销正常
```

**24000 倍**的体积差。

### 一点代价

点级备份**不支持重做**（redo 需要知道「改后的值」，点级只存了「改前的值」）。
撤销时会提示「已撤销 N 个像素的改动（点级备份，不支持重做）」。
包围盒备份仍然支持完整重做。

这个取舍划算：33 MB 换一次重做，不值。
