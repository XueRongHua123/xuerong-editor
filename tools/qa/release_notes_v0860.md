## 雪绒的钢铁雄心编辑器 v0.86.0

接入**游戏日志检查**：跑完一局游戏，编辑器直接告诉你日志里在报什么。

### 为什么做这个

静态检查只能看文件写得对不对，看不了"游戏实际怎么想"。`error.log` 是唯一的权威——
它记录引擎在运行时遇到的每一个问题。1.14 MB 的日志人工翻一遍要十几分钟，编辑器读一遍 1 秒。

### 新增

`项目体检` 里现在会混入日志条目（kind = log），按类别聚合：

| 级别 | 类别 | 本项目实测（1.14 MB / 7316 行） |
|---|---|---|
| 错误 | 脚本语法错误 | 22 条（`doctrines/.../special_forces_subdoctrines.txt` ×10 等） |
| 警告 | 铁路等级超上限 | 442 条 |
| 警告 | 使用了已弃用的属性 | 154 条（`ai_templates/generic.txt` ×84、`templates_BET.txt` ×70） |
| 警告 | 无效的 trigger | 120 条 |
| 提示 | 缺少 3D 实体 | 2451 条 |
| 提示 | 音效缺失或重复 | 506 条（`ww_vo.asset` ×192、`gtd_gui.asset` ×42） |
| 提示 | 引用了不存在的 GFX | 472 条 |
| 提示 | descriptor 版本号写法 | 2 条 |

每条都带「涉及文件 ×次数」和一句修复建议。

### 顺带：铁路等级改成静态检查

日志里 442 条 `Railway level > MAX_RAILWAY_LEVEL`，现在不跑游戏也能查：

- 支持两种写法：`railway = { level = N provinces = {...} }` 与 MUVLUV 用的行式 `level count p1 p2 ...`
- 本项目 railways.txt 1666 条、原版 909 条，超限均为 0（那 442 条来自当时加载的其它 mod）

### 接口

- `GET /api/log[?path=...]` —— 单独取日志解析结果（含全部涉及文件排行）
- `GET /api/lint` —— 体检里自动混入日志条目

### 关于参考项目

对照了 `Pra-Moon/hoi4-ai-modding-skills` 的验证脚本：

- 它的「括号配对」是**裸计数**，对 `MVLV_names.txt` 这类含引号字符串的文件误报不平衡；
  用我们的解析器（考虑引号与注释）核验，那 5 个文件全部平衡（净深度 0）
- 所以只借它的**规则清单**（BOM 规范、1.19 modifier 改名、引用闭环），不借实现

BOM 规范与 modifier 改名检查留到下一版（需要先确认对我们的写入流程没有副作用）。
