## 雪绒的钢铁雄心编辑器 v0.99.0

**涂色实操验通 + 省份合并 + 一批性能修复**。

### 1. 涂色在真实副本上跑通

用 33 MB 的 `provinces.bmp` 副本完整走了一遍前端流程：

```
切涂色模式 → 填目标省 221 → 笔刷 6px → 拖动涂抹
→ 待涂 678 像素 → 点「应用」→ 文件被写入
→ 点「撤销上一笔」→ md5 与原文件完全一致
```

0 报错。界面与后端都是通的。

### 2. 省份合并（新功能）

涂色面板下方新增「省份合并」：

1. 填要合并掉的省号 → 点「看相邻省」→ 列出相邻省及共享边像素数（可点选）
2. 点「预览影响」→ 显示会改多少像素、影响哪些州/战略区、有没有州会变空
3. 点「执行合并」→ 写 bmp + 改写相关州文件的省份列表

实测（副本）：省 221 → 2824，87 像素，影响州 125、战略区 1，0 报错。

### 3. 性能：预览从 6.4 秒降到 0.13 秒

这是本版最有价值的部分。合并预览原来要 6.4 秒，查下来是三处问题：

| 问题 | 原因 | 修法 | 效果 |
|---|---|---|---|
| `mod_layers()` 每次重扫 workshop 目录 | 递归找父 mod 时对几百个目录各读一次 descriptor | 加 mtime 缓存 | 省下约 1 秒 |
| `_strategic_regions()` 每次重解析 222 个文件 | 无缓存 | 加 mtime 缓存 | 1.6 秒 → 0 |
| `bmp_read_rect` 逐像素手工解析 | Python 层 1100 万次 append | 改 Pillow 的 crop+tobytes | 7 秒 → 2.8 秒 |
| 预览为了数像素读整幅 | 其实只需一个计数 | 读图层缓存的 `prov_index.json`，缺失时用 `getcolors(200000)` | 2.8 秒 → 0.28 秒 |

**合并预览 6400ms → 132ms（快 48 倍）**。这些缓存对地图检查、图层构建、涂色全都生效。

顺带发现：Pillow 的 `getcolors(maxcolors=1<<24)` 会因为分配 1600 万槽的数组而慢到 8 秒，
改成按实际颜色数量级（20 万）后只要 280ms。

### 4. 相邻省查询

整幅扫描一次约 4.4 秒，按 bmp 的 mtime 缓存，同一个省第二次 0ms。

### 已知限制

- 合并目前不改 `definition.csv`（源省定义仍保留，检查里会显示为"幽灵省"，可后续用显式删除清掉）
- 合并撤销用整幅备份（33 MB 一次），因为影响面可能很大
- 相邻省首次查询仍需 4 秒（有 loading 提示）
