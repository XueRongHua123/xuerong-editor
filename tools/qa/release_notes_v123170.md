## 雪绒的钢铁雄心编辑器 v1.23.17

新建人物不再覆盖原版同名文件。

### 上一版留下的坑

v1.23.16 让 `character_add` 写到 `common/characters/<TAG>.txt`，解决了「人物不显示」。
但那个文件名和原版同名，直接写就是**整体覆盖**：

```
原版 GER.txt    85318 字节，几百个人物
我们的 GER.txt    180 字节，只有「测试将军」
```

德国几百个将领全被删掉，游戏里只剩一个测试将军。

### 改法

写入前先检查目标文件存不存在，不存在就从生效链里找同名的原版文件复制过来，
再往里面追加：

```python
if not os.path.exists(p):
    src = 找到 <TAG>.txt 的源
    if src: 复制
# 然后按原来的逻辑往 characters = {} 里追加
```

### 实测

```
已新建人物「测试将军」（XTT_Gen，field_marshal）
文件大小: 85481     ← 原版 85318 + 我们 163 字节
有 XTT_Gen: True
有原版 adolf_hitler: True
```

原版将领全在，新的追加成功。

### `unit_add` 不受影响

它用的是 `<TAG>_1936_zz.txt` 这种新文件名，原版没有同名文件，
不会覆盖任何东西。

### 这个坑的性质

「写到同名文件」这件事本身是对的（HOI4 就要同名），
但**写之前必须先有原版那份**，否则就是删除。

同类风险还有 `country_save`（写 `history/countries/<TAG> - Name.txt`），
那个走的是单文件接管，已经会先复制，没问题。
